# Exploratory pass: SQL transactions and backup

Date: 2026-11-05. Base: `3392723` on `origin/main`. The test used Linux amd64, Go 1.26.10, and Go MySQL driver 1.9.3. The operator build reported version 0.2.20 and build identity `local`. The [version](2026-11-05-wire/version.PBdVby/output.log) and [executable hash](2026-11-05-wire/sha256.4sqnbA/output.log) are recorded.

The pass used a fresh data directory, a trial password, and loopback ports 43459 and 43460. Module and build caches were private to the worktree. `go mod download` and `make build` used `-mod=readonly` and the checked-in `go.sum`. The [run script](2026-11-05-wire/run.sh.txt) registered server PIDs and used an exit trap. The [client](2026-11-05-wire/client.go.txt) used the public MySQL protocol. The [variation script](2026-11-05-wire/variation.sh.txt) tested a rejected restore. Both scripts ran inside the worktree. Captured log lines have trailing whitespace removed.

## Results

### Create data and use a savepoint

The server returned HTTP 200 from `/ready` and accepted an authenticated client. The client created a database and inserted two tasks. The README prepared query with parameter 2 returned `2, test query behaviour`. In a transaction, the client changed task 1 to priority 3, created a savepoint, changed task 2 to priority 9, rolled back to the savepoint, and committed. The result was priorities `3, 2`. After a server restart, both titles and priorities remained intact. See the [actions and results](2026-11-05-wire/client-create.DTk7VJ/output.log) and [restart result](2026-11-05-wire/client-restart.MegKZc/output.log).

### Inspect planned and completed queries

For the post-transaction filter, planned JSON reported `mode: plan`. Analyzed JSON reported `mode: analyze`, `complete: true`, and two output rows at the root. The saved data contains two matching rows. The planned and analyzed scan identified the primary index as non-covering and gave consistent coverage evidence. This is a different projection from the original reproducer in the closed [issue #590](https://github.com/jonbaldie/database/issues/590), so this pass does not independently retest that fix. See the [query output](2026-11-05-wire/client-create.DTk7VJ/output.log).

### Back up and restore an instance

The online backup command succeeded. Backup inspection reported a complete archive with valid integrity. Restore into a new directory succeeded, and the restored server returned both committed rows with priorities `3, 2`. See the [backup](2026-11-05-wire/backup.aJ8FqC/output.log), [inspection](2026-11-05-wire/inspect.ndBwh8/output.log), [restore](2026-11-05-wire/restore.iC2DFw/output.log), and [restored rows](2026-11-05-wire/client-restore.Q1aqiq/output.log).

As a variation, restore into the original nonempty directory returned exit code 3 and `target_state: left_unchanged`. A restart returned the same two rows. See the [rejection](2026-11-05-wire/restore-nonempty.gQdCff/output.log) and [rows after rejection](2026-11-05-wire/client-after-rejected-restore.aWhiJ7/output.log).

# Exploratory pass: local trial and query explanation

Date: 2026-10-28. Base: `4cb58ec` on `origin/main`. Linux amd64, Go 1.26.10, Go MySQL driver 1.9.3. The operator executable reported version 0.2.19 and build identity `local`. The [version](2026-10-28-trial/version.G34zL2/output.log) and [SHA-256](2026-10-28-trial/sha256.hE6RJJ/output.log) are recorded.

The pass used fresh data directories, loopback ports 33377 and 38077, and a trial-only password. Module and build caches were private to the worktree. `go mod download` and the build used `-mod=readonly`. The [run script](2026-10-28-trial/run.sh.txt) registered each server PID and used an exit trap. The [client](2026-10-28-trial/client.go.txt) drove the public MySQL protocol. The [replay](2026-10-28-trial/replay.sh.txt) used a second fresh data directory. The scripts were run from `.scratch` in the worktree; the copies here are evidence, not standalone launchers.

## Results

### Start, inspect, and restart a server

The initial account and data directory were created with the operator CLI. The server returned HTTP 200 from `/ready`, accepted an authenticated client, and stopped on SIGTERM. A second server opened the same directory and returned the saved rows. [First run log](2026-10-28-trial/run.log), [readiness](2026-10-28-trial/ready.70dpav/output.log), and [reopened rows](2026-10-28-trial/client-reopen.r7WLDa/output.log). Initial connection errors during the readiness polling preceded readiness and did not recur after readiness.

### Create, query, and roll back data

The client created a database and a table, inserted two rows, and selected the row with priority at least 2. The result was `2, test query behaviour`. As a variation, it changed row 1 in a transaction and rolled back. Priorities remained `1, 2` and both rows retained their values after restart. [Actions and results](2026-10-28-trial/client-create.PDt7xw/output.log). The process tests for the Go driver, session persistence, and B-tree indexes also passed. [Test output](2026-10-28-trial/sql.qPTewg/output.log).

### Inspect a query plan and its execution

The client requested planned and analyzed JSON for the same filter. The ordinary query returned one row. The analyzed plan recorded one output row and completed execution. The planned and analyzed output both contained contradictory index-coverage evidence. A second fresh data directory reproduced the contradiction in both forms. [First output](2026-10-28-trial/client-create.PDt7xw/output.log), [replay](2026-10-28-trial/client-create.ZXFSzH/output.log).

**Confirmed bug:** [#590](https://github.com/jonbaldie/database/issues/590). A scan identified as `btree_covering_index_scan` says it uses an index containing every projected value, while its `INDEX_COVERAGE` opportunity asserts that the selected path reads table rows after traversal. This can mislead a developer who tunes the query. The issue contains the starting state and SQL steps. This observation does not establish which storage reads occurred.

## Verification and limits

The mapped lifecycle, SQL, and explanation process tests passed twice with `DATABASE_BLACKBOX_EXECUTABLE` unset. They built their own temporary test executable, not the operator executable identified above. Their output is in [lifecycle](2026-10-28-trial/lifecycle.dB4RLN/output.log), [SQL](2026-10-28-trial/sql.qPTewg/output.log), and [explanation](2026-10-28-trial/explanation.xpAaQn/output.log). Each evidence attempt includes its command and exit status. The process-test helper owns its temporary server processes and data.

There were no unresolved product observations. The pass did not exercise backup, restore, other client languages, concurrent writes, or non-loopback access. It did not test the exact prepared query from the README trial. No product fix was made. Existing issues and closed rejections were searched before filing #590; no matching issue was found.

The two runs stopped and waited for all four manual server PIDs. The cleanup check found no listeners on either selected port and no surviving registered PIDs. No containers or browser sessions were started.

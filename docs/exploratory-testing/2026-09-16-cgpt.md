## Properties

### Stateful SQL model

The executable property is `FuzzBlackBoxSQLStateful` in
`test/blackbox/cgpt_stateful_test.go`.

Each generated case starts from a new instance through `init` and `serve`, then
uses one authenticated MySQL wire session to create `cgpt.items`. A byte input
decodes to at most 32 typed actions:

- Insert a new integer primary key and value.
- Update an existing row.
- Delete an existing row.
- Insert a duplicate primary key.
- Insert `NULL` into a `NOT NULL` column.

The independent model stores the expected sorted rows. After every action, the
harness reads `SELECT id, value FROM items ORDER BY id` and compares the rows
with the model. Duplicate inserts must return error `1062`. Null inserts must
return error `1048` and must not change the model or stored rows. The session
must remain usable after either failure.

The metamorphic step closes the session, gracefully stops the server, starts the
same data directory again, and compares the fresh-session rows with the model.
This tests that restart preserves the committed result.

The setup is always valid. Actions with no existing row are discarded as
no-operations by the generator. No generated SQL identifier or value comes from
unescaped arbitrary text.

### Generator, mutator, and shrink

The Go fuzz engine decodes arbitrary `[]byte` values into the typed action
sequence. It starts with three seeds and mutates successful seeds according to
new harness execution paths. The action decoder reuses the input bytes for
operation kind, row selection, and bounded integer values.

The property shrinks naturally through Go fuzzing. The final harness also caps
the sequence at 32 actions and reduces row choices to existing sorted keys.
The smallest useful failure would retain only the schema setup, one failing
write or state change, the ordered read, and the restart if restart is required.

### Coverage

The ordinary campaign used Go fuzz coverage in the public black-box property
and wire harness. A second campaign used a production binary built with:

```sh
go build -cover -coverpkg=./... -trimpath -buildvcs=false \
  -o /tmp/database-cgpt-20260916/database-covered ./cmd/database
```

The covered binary inherited `GOCOVERDIR` and wrote coverage when each real
server process stopped. The production coverage was collected with
`go tool covdata`. This proves coverage through the SUT code, not only through
the test framework.

The native Go fuzz engine uses coverage from the test process for live guidance.
Go does not feed coverage from a separate child process back into the native
fuzz engine. The child production coverage is therefore measurement evidence,
not direct native-fuzzer feedback. A future campaign can add a custom
supervisor if direct child-coverage feedback is required.

The remaining diagnostics were classified as deferred non-bug diagnostics for
this campaign. They identify style, unused code, or simplification changes and

## Findings

No stable counterexample was found. No product bug was filed.

The harness remains in `test/blackbox/cgpt_stateful_test.go` and supports a
replayable seed run with:

```sh
GOMAXPROCS=2 GOFLAGS='-p=2' \
go test ./test/blackbox -run '^FuzzBlackBoxSQLStateful$' \
  -count=1 -parallel=1 -timeout=2m
```

## Limits

- The property covers auto-commit DML and restart durability. It does not yet
  generate transactions, savepoints, lock cycles, account grants, backup and
  restore, or configuration source combinations.
- Native fuzz guidance uses the test process. Production child coverage was
  collected, but it was not used as direct feedback by the native fuzzer.
- The supplemental `staticcheck` findings were not all converted to separate
  system reproducers. The two path-sensitive value-use findings were checked
  through reachable public workflows; the remaining findings remain deferred.

# MySQL compatibility surface used by application drivers

Research date: 2026-07-15

## Decision summary

“Works with a MySQL driver” should be specified separately from “accepts MySQL application SQL.” Drivers mostly transport SQL written by applications; supporting a driver therefore gives us a finite wire, session, result, and metadata contract, but it does not define a finite SQL dialect. For example, Go’s driver sends caller SQL through `COM_QUERY`, and mysql2 does the same for `query()`; both have separate server-prepared-statement paths.[Go query source](https://github.com/go-sql-driver/mysql/blob/b96d41506ad9d74622faf53364cb92ba9aea2e6c/connection.go) [mysql2 query source](https://github.com/sidorares/node-mysql2/blob/f86cfb18bb507cbe7cefb29cee849604318d5171/lib/commands/query.js) [mysql2 prepare/execute source](https://github.com/sidorares/node-mysql2/blob/f86cfb18bb507cbe7cefb29cee849604318d5171/lib/base/connection.js)

The sensible compatibility target is therefore:

1. **Connection baseline:** current clients can authenticate, select a schema, ping, run a text query, receive correct rows or errors, and close.
2. **Ordinary application baseline:** add transactions, server-side prepared statements, correct type/column metadata, affected-row and generated-ID reporting, and multi-result draining.
3. **Tooling profile:** add the metadata SQL actually required by chosen tools (`INFORMATION_SCHEMA`, `SHOW`, `DESCRIBE`, `EXPLAIN`, and a few session-variable queries). This must be tested and scoped tool by tool rather than inferred from the wire protocol.

This boundary is consistent across the requested first-party clients. Connector/J documents server-side prepared statements and configurable result/type conversion; Connector/Python exposes a prepared cursor plus explicit transaction/session APIs; Go and mysql2 expose the same text-query versus prepared-query split.[Connector/J prepared statements](https://dev.mysql.com/doc/connector-j/en/connector-j-connp-props-prepared-statements.html) [Connector/J type conversions](https://dev.mysql.com/doc/connector-j/en/connector-j-reference-type-conversions.html) [Connector/Python prepared cursor](https://dev.mysql.com/doc/connector-python/en/connector-python-api-mysqlcursorprepared.html) [Connector/Python transactions](https://dev.mysql.com/doc/connector-python/en/connector-python-api-mysqlconnection-start-transaction.html) [Go statement source](https://github.com/go-sql-driver/mysql/blob/b96d41506ad9d74622faf53364cb92ba9aea2e6c/statement.go) [mysql2 prepare/execute source](https://github.com/sidorares/node-mysql2/tree/f86cfb18bb507cbe7cefb29cee849604318d5171/lib/commands)

Do not advertise a capability until its complete state machine is implemented. MySQL defines negotiation as the intersection of server and client capability flags; flags alter packet layouts and semantics, including TLS, authentication, result terminators, session tracking, and multiple results.[Connection phase](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_connection_phase.html) [Capability flags](https://dev.mysql.com/doc/dev/mysql-server/latest/group__group__cs__capabilities__flags.html)

## Compatibility matrix

|---|---|---|
| P0 | Classic packet framing | Implement the three-byte payload length, sequence ID, packet splitting/reassembly, length-encoded integers/strings, and command-boundary sequence resets. These are the building blocks under every following exchange.[MySQL packets](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_basic_packets.html) [Integer encodings](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_basic_dt_integers.html) [String encodings](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_basic_dt_strings.html) |
| P0 | Protocol 10 / 4.1 handshake | Send `HandshakeV10`; correctly intersect capabilities; accept `HandshakeResponse41`, including username, optional database, collation, auth plugin and connection attributes. The current Go driver rejects pre-4.1 protocol and sends a 4.1 response with these fields.[HandshakeV10](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_connection_phase_packets_protocol_handshake_v10.html) [HandshakeResponse41](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_connection_phase_packets_protocol_handshake_response.html) [Go handshake implementation](https://github.com/go-sql-driver/mysql/blob/b96d41506ad9d74622faf53364cb92ba9aea2e6c/packets.go) |
| P0 | TLS and authentication state machine | Honor `CLIENT_SSL` and the pre-authentication `SSLRequest`; support plugin selection/switching, `AuthMoreData`, and success/error completion. `caching_sha2_password` has cached fast authentication and full authentication, the latter requiring a secure connection or encrypted password exchange. Current MySQL documentation also notes that `mysql_native_password` was removed server-side in MySQL 9.0, so it is a legacy compatibility option, not the modern baseline.[Connection phase](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_connection_phase.html) [`caching_sha2_password`](https://dev.mysql.com/doc/dev/mysql-server/latest/page_caching_sha2_authentication_exchanges.html) [Go authentication paths](https://github.com/go-sql-driver/mysql/blob/b96d41506ad9d74622faf53364cb92ba9aea2e6c/auth.go) |
| P0 | Basic commands | Implement at least `COM_QUERY`, `COM_INIT_DB`, `COM_PING`, `COM_QUIT`. `COM_PING` must return an OK packet. Schema may also be selected in the handshake with `CLIENT_CONNECT_WITH_DB`.[Command phase](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_command_phase.html) [`COM_QUERY`](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_com_query.html) [`COM_PING`](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_com_ping.html) [Capability flags](https://dev.mysql.com/doc/dev/mysql-server/latest/group__group__cs__capabilities__flags.html) |
| P0 | Generic responses and text result sets | Return protocol-correct OK, ERR, and result-set packets. OK must preserve affected rows, last insert ID, status flags and warning count. ERR must preserve numeric error code, five-character SQLSTATE and message. Text results require the column count, full column definitions, text rows, NULL encoding and negotiated EOF/OK termination.[OK packet](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_basic_ok_packet.html) [ERR packet](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_basic_err_packet.html) [Text result set](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_com_query_response_text_resultset.html) |
| P0 | Bootstrap/session SQL | Parse and execute `SELECT @@variable`, `SET ...`, `SET NAMES ... [COLLATE ...]`, and transaction statements used by drivers. Go queries `@@max_allowed_packet`, optionally sends `SET NAMES`, maps arbitrary DSN session parameters to `SET`, and implements isolation/read-only transactions with `SET TRANSACTION ...` and `START TRANSACTION`.[Go connection setup](https://github.com/go-sql-driver/mysql/blob/b96d41506ad9d74622faf53364cb92ba9aea2e6c/connector.go) [Go session/transaction SQL](https://github.com/go-sql-driver/mysql/blob/b96d41506ad9d74622faf53364cb92ba9aea2e6c/connection.go) [Connection character sets](https://dev.mysql.com/doc/refman/8.4/en/charset-connection.html) |
| P1 | Server-prepared statements | Implement the full lifecycle: `COM_STMT_PREPARE` and its parameter/column metadata; `COM_STMT_EXECUTE` with NULL bitmap, parameter types, unsigned flag and binary values; `COM_STMT_SEND_LONG_DATA`; `COM_STMT_RESET`; and `COM_STMT_CLOSE`. Prepared results use binary rows, not text rows. The requested Go, Java, Python and Node clients all expose this server-prepared path.[`COM_STMT_PREPARE`](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_com_stmt_prepare.html) [`COM_STMT_EXECUTE`](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_com_stmt_execute.html) [`COM_STMT_SEND_LONG_DATA`](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_com_stmt_send_long_data.html) [Binary result sets](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_binary_resultset.html) [Go statement source](https://github.com/go-sql-driver/mysql/blob/b96d41506ad9d74622faf53364cb92ba9aea2e6c/statement.go) [Connector/J prepared statements](https://dev.mysql.com/doc/connector-j/en/connector-j-connp-props-prepared-statements.html) [Connector/Python prepared cursor](https://dev.mysql.com/doc/connector-python/en/connector-python-api-mysqlcursorprepared.html) [mysql2 prepare/execute source](https://github.com/sidorares/node-mysql2/tree/f86cfb18bb507cbe7cefb29cee849604318d5171/lib/commands) |
| P1 | Column metadata fidelity | Populate catalog, schema, logical/original table and column names, character set, length, type, flags and decimals accurately. Drivers use these fields to decide host-language type, signedness, binary versus text, nullability, precision/scale, aliases, and JSON/date handling; plausible-looking row bytes with wrong metadata still produce wrong application values.[ColumnDefinition41](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_com_query_response_text_resultset_column_definition.html) [Go metadata mapping](https://github.com/go-sql-driver/mysql/blob/b96d41506ad9d74622faf53364cb92ba9aea2e6c/fields.go) [Go `RowsColumnType` implementation](https://github.com/go-sql-driver/mysql/blob/b96d41506ad9d74622faf53364cb92ba9aea2e6c/rows.go) [mysql2 column parser](https://github.com/sidorares/node-mysql2/blob/f86cfb18bb507cbe7cefb29cee849604318d5171/lib/packets/column_definition.js) |
| P1 | Ordinary type families in both encodings | Cover NULL; signed and unsigned integer widths; `DECIMAL`; float/double; character and binary strings/BLOBs; `BIT`; `DATE`, `TIME`, `DATETIME`, `TIMESTAMP`, `YEAR`; and JSON in both text and binary rows. | P1 | Transaction and session semantics | Preserve session-local current schema, autocommit, isolation/read-only mode, SQL mode, time zone, charset/collation, user variables, temporary objects and open transaction state across commands on one connection. | P1 | Multiple results and draining | Honor `SERVER_MORE_RESULTS_EXISTS` and return/drain every result after multi-statements or stored routines. | P1 | Error identity and statement outcome | Match MySQL error number and SQLSTATE for compatibility-sensitive failures, not merely the message. | P2 | Pool reset and session tracking | Support `COM_RESET_CONNECTION` before advertising or documenting pool reset; it clears session state without reconnecting or reauthenticating. `CLIENT_SESSION_TRACK` changes OK-packet layout and can report schema and system-variable changes, so either implement it fully or do not advertise it.[`COM_RESET_CONNECTION`](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_com_reset_connection.html) [OK session-state payload](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_basic_ok_packet.html) [mysql2 reset API](https://github.com/sidorares/node-mysql2/blob/f86cfb18bb507cbe7cefb29cee849604318d5171/lib/base/connection.js) |

## Highest compatibility risks

1. **Capability negotiation creates hidden packet-contract branches.** A single incorrect flag changes what the other side sends. The most dangerous early examples are `CLIENT_SSL`, `CLIENT_PLUGIN_AUTH`, `CLIENT_DEPRECATE_EOF`, `CLIENT_SESSION_TRACK`, `CLIENT_MULTI_RESULTS`, and prepared-statement metadata flags.[Capability flags](https://dev.mysql.com/doc/dev/mysql-server/latest/group__group__cs__capabilities__flags.html)
2. **Authentication is a state machine, not one hash check.** Modern `caching_sha2_password` must handle cache hit, cache miss/full authentication, TLS versus RSA, plugin switching, and failure packets. It should be tested with a cold auth cache as well as a warm one.[`caching_sha2_password`](https://dev.mysql.com/doc/dev/mysql-server/latest/page_caching_sha2_authentication_exchanges.html) [Connection authentication flow](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_connection_phase.html)
3. **Metadata errors silently corrupt host-language values.** Unsigned `BIGINT`, exact decimal, binary/text, temporal values, JSON and NULL are all decoded using column metadata; this is a higher risk than simple string-only query tests reveal.[ColumnDefinition41](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_com_query_response_text_resultset_column_definition.html) [Go field mapping](https://github.com/go-sql-driver/mysql/blob/b96d41506ad9d74622faf53364cb92ba9aea2e6c/fields.go) [mysql2 parsers](https://github.com/sidorares/node-mysql2/tree/f86cfb18bb507cbe7cefb29cee849604318d5171/lib/parsers)
4. **Prepared statements are effectively a second protocol.** They add statement IDs and lifetime, parameter metadata, long-data chunks, NULL bitmaps, type reuse, binary values, binary rows, and reset/close behavior.[Prepared statements](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_com_stmt_prepare.html) [`COM_STMT_EXECUTE`](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_com_stmt_execute.html)
5. **Session leakage breaks pooled applications.** Current schema, autocommit, transaction state, SQL mode, time zone and charset must evolve coherently across commands and reset coherently when reset is supported.[Server session variables](https://dev.mysql.com/doc/refman/8.4/en/server-system-variables.html) [`COM_RESET_CONNECTION`](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_com_reset_connection.html)
6. **Tool compatibility rapidly becomes SQL compatibility.** The mysql CLI’s status command alone issues `SELECT DATABASE(), USER()` and charset-variable queries, while driver metadata APIs and migration tools add `INFORMATION_SCHEMA`, `SHOW`, `DESCRIBE` and `EXPLAIN`. Each chosen tool needs a captured compatibility suite; this should not be allowed to silently expand the initial wire-protocol milestone.[mysql client implementation](https://github.com/mysql/mysql-server/blob/d229bb760c49b65e19ec28342236961ad961d7fe/client/mysql.cc) [mysql client commands](https://dev.mysql.com/doc/refman/8.4/en/mysql-commands.html)

## Explicitly optional for the first application baseline

Compression, `LOAD DATA LOCAL INFILE`, multi-statements in one `COM_QUERY`, query attributes, server cursors/`COM_STMT_FETCH`, `COM_CHANGE_USER`, replication/binlog commands, X Protocol, and every authentication plugin beyond the selected account policy are all real ecosystem surfaces, but ordinary query/transaction/prepared-statement use does not require enabling them. Several appear as opt-in driver settings or specialist APIs in Go and mysql2.[Go DSN options](https://github.com/go-sql-driver/mysql/blob/b96d41506ad9d74622faf53364cb92ba9aea2e6c/README.md) [mysql2 connection options](https://github.com/sidorares/node-mysql2/blob/f86cfb18bb507cbe7cefb29cee849604318d5171/lib/connection_config.js) [MySQL command phase](https://dev.mysql.com/doc/dev/mysql-server/latest/page_protocol_command_phase.html)

This optional list is not permission to return malformed responses. Unsupported features must be omitted from the server capability set or rejected with a protocol-correct MySQL error.

## Recommended acceptance suite

Run the same black-box cases through the unmodified Go, Java, Python and Node drivers, then add the mysql CLI smoke profile:

- plain and TLS connections; wrong password; warm and cold `caching_sha2_password` authentication;
- schema in DSN, schema switch, ping and clean close;
- text query and prepared query over the full baseline type matrix, including NULL, maximum unsigned integer, exact decimal, binary bytes, Unicode, fractional temporal values and JSON;
- column aliases plus metadata assertions for name, database type, signedness, nullability and precision/scale;
- insert/update/delete outcomes: generated ID, affected rows, warning and duplicate-key error identity;
- commit, rollback, autocommit changes, isolation/read-only selection and connection reuse;
- multi-row and multi-result streaming with early row closure/draining;
- mysql CLI query, `use`, `warnings` and `status`.

Driver-specific metadata/tooling SQL should be recorded from this suite and promoted into the SQL compatibility profile only when a supported user journey requires it.
